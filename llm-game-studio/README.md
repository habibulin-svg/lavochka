# LLM Game Studio

Локальная студия для автономной разработки игр на своих моделях: картинки, видео, музыка, звуки, озвучка,
тексты и код — по **скрипту**, который пишет любая LLM. Веб-интерфейс на своём компьютере,
прогресс и результаты в реальном времени, подбор моделей под железо, докачка недостающего.

```
скрипт LGS (от Claude / ChatGPT / локальной LLM)
   → проверка и план: какие модели, на какой карте, что докачать
   → загрузка недостающего (Hugging Face → зеркала → ModelScope, с докачкой)
   → запуск: ComfyUI и llama-server поднимаются сами, шаги идут параллельно по картам
   → превью каждого файла по мере готовности, пауза на отбор человеком
   → выход + manifest.json (промпт, сид, модель, лицензия у каждого файла)
```

## Запуск

Нужен только **Python 3.11+** — сторонних пакетов нет (PyYAML лежит в `vendor/`).

```bash
llm-game-studio/start.cmd
```

или `python llm-game-studio/run.py` (`--port 7870`, `--no-browser`). Откроется `http://127.0.0.1:7870/`.

Модели и движки студия ищет сама: если есть `G:\ai\ai.json` (стек этой машины) — берёт пути, порты и роли карт оттуда;
иначе кладёт всё в `llm-game-studio/data/`. Пути меняются на вкладке «Настройки».

## Вкладки

| Вкладка | Что там |
|---|---|
| **Обзор** | видеопамять и загрузка карт, RAM, серверы моделей, запуски, загрузки — всё живое |
| **Скрипт** | редактор: вставить текст, перетащить файл, открыть пример; «Проверить» → план, «Скачать недостающее», «Запустить» |
| **Запуски** | шаги с прогрессом и статусом, журнал, галерея результатов (картинки, видео, звук, текст), отбор, отмена, повтор |
| **Железо и подбор** | процессор, память, карты (CUDA, полоса), кто держит видеопамять; лучшая модель на каждую задачу; **профили llama-server** под ваши карты |
| **Модели** | каталог: что на диске, что влезает, лицензия; скачать (у LLM — выбор кванта), проверить источник, добавить любую с Hugging Face |
| **Сервисы и движки** | ComfyUI на каждой карте и llama-server: запуск/остановка, журнал; установка llama.cpp с GitHub под нужную CUDA; питон-окружения раннеров |
| **Формат скрипта** | описание формата + кнопка «Скопировать промпт для LLM» (формат + модели и железо этой машины) |
| **Настройки** | пути, порты, роли карт, зеркала, токен HF, только IPv4 |

## Скрипт

Формат — [SCRIPT_FORMAT.md](SCRIPT_FORMAT.md). Его целиком отдают LLM: «напиши скрипт LGS для …».
Коротко: YAML, `lgs: 1`, `name`, список `steps`; у шага `uses` — тип: `image`, `video`, `upscale`, `cutout`, `music`,
`sfx`, `tts`, `asr`, `llm`, `vlm`, `code`, `comfy`, `python`, `shell`, `approve`, `service`. Единицы работы —
`items` × `seeds`, или из файла прошлого шага (`items_from`), или по файлам (`inputs`). Модель и карта — `auto`.

Примеры — [examples/](examples/): `demo-no-gpu.yaml` (проверка без видеокарты), `kiosk.yaml` (идеи → картинки → отбор →
вырезка → звуки), `voices.yaml` (озвучка + лучший дубль по Whisper), `qa-sheet.yaml` (VLM отбраковывает картинки),
`code-leaf.yaml` (локальная LLM пишет модуль под тест). Свои скрипты кнопка «Сохранить» кладёт в `scripts/`.

## Подбор под железо

- **Задачи (картинки, видео, звук…)** — лучшая по качеству модель, которая влезает: тяжёлое на большую карту, лёгкое на малую
  (роли карт — в настройках).
- **LLM** — для каждой модели и кванта считается раскладка: веса + кэш контекста (по шапке GGUF — точно, иначе оценка) +
  запас на карту. Два режима: **все карты под LLM** (`-ts` по объёму карт, `-sm layer`) и **рядом с генерацией**
  (малая карта + оперативная память; у MoE эксперты уходят в RAM через `--n-cpu-moe`). Контекст — самый длинный,
  при котором веса целиком на картах. Скорость — оценка по полосе памяти; «Замерить» запускает модель и меряет по-настоящему
  (история — `data/bench.json`).
- Сервер, которому шагу не хватает видеопамяти, студия останавливает, **если запускала его сама**. Чужие (LM Studio,
  ComfyUI, запущенный вручную) — не трогает; остановить их можно только явно на вкладке «Сервисы».

## Устройство

```
lgs/              сервер (только стандартная библиотека)
  server.py       HTTP + API + поток событий (SSE) для интерфейса
  config.py       настройки: data/config.json поверх найденного на машине
  hardware.py     nvidia-smi, память, процессор, диски
  gguf.py         шапка GGUF: слои, головы, кэш на токен
  catalog.json    каталог моделей: файлы, куда класть, видеопамять, качество, лицензия
  catalog.py      что установлено; advisor.py — подбор и профили llama-server
  download.py     очередь загрузок с докачкой и запасными источниками
  services.py     llama-server и ComfyUI: запуск, журнал, «внешний»/«свой»
  engines.py      llama.cpp с GitHub, окружения раннеров
  script.py       формат: разбор, проверка, ${...}, развёртка единиц
  runner.py       план, расписание шагов по картам, прогресс, манифест, отбор
  steps_*.py      исполнители шагов: ComfyUI, LLM (llm/vlm/code), процессы
runners/          питон-раннеры моделей (запускаются в своих окружениях): stable_audio, qwen_tts, whisper, birefnet
workflows/        графы ComfyUI (API-формат) с {{подстановками}}
ui/               интерфейс: index.html, app.js, style.css — без сборки
examples/         примеры скриптов
tests/            python -m unittest discover -s llm-game-studio/tests
vendor/yaml       PyYAML 6.0.3 (MIT)
data/             (не в git) настройки, журналы, запуски, свои модели
```

Протокол своих скриптов (`python`/`shell`): строки `@progress 3/10 текст` и `@output путь {json}` в stdout —
прогресс и превью. Раннеры моделей говорят на нём же (`runners/_lgs.py`).

## Чего пока нет

- ComfyUI студия не ставит (только находит и запускает) — ставится его portable-сборкой.
- Внутри одной картинки/ролика прогресс по шагам семплера не показывается (только «единица N из M» и время).
- 3D (TripoSG) и Blender — пока шагом `python` со своим скриптом, без встроенного раннера.
- Только видеокарты NVIDIA (AMD/Apple — через CPU-сборку llama.cpp).
