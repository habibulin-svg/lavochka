# Глубокое ревью: «Вкладыши» (vkladyshi)

Проверено: src/games/vkladyshi/ (engine, def, bot, cards, collection, bank, view, home, music), связь с server/vkladyshi.ts.

## Находки

1. **Важно (не в папке игры, не трогал)** — server/vkladyshi.ts:340. В `start()` колода игрока подставляется в `opts['deckN']` только если
   `!deckValid(c, d.ids)`. Если у вошедшего активная колода невалидна (не 20 карт, лишние копии), в опциях остаётся то, что прислал хозяин комнаты.
   Хозяин может задать себе `deck0 = 'c:...'` с любыми 20 вкладышами (движок `deckFrom` проверяет только существование карт и «не больше двух»,
   владение не проверяет), в том числе при включённом коне. Починка: в `else` ставить стартовую колоду (`'garage'`) для места, где сидит вошедший,
   и вообще вычищать `deckN` вида `c:` для мест без валидной серверной колоды, когда есть кон. Статус: **спорно / передаю** (чужая зона по заданию).
2. **Средне (исправлено)** — def.ts:211. Опция `hero` брала любое число из комнаты: `-5`/`0` давали партию, законченную до первого хода
   (`over` на старте, ничья), что при коне можно использовать как «отмену» невыгодной ставки. Теперь допустимы только значения из списка выбора 20/30/40,
   иначе 30. Тест: tests/vkladyshi.test.ts «Вкладыши: опции комнаты».
3. **Мелко (исправлено)** — view.ts destroy: не сбрасывался таймер долгого нажатия `pressT`. Теперь `clearTimeout(pressT)`.
4. **Мелко (спорно)** — music.ts: быстрый `stop()` -> `play()` во время ожидания списка треков может запустить две цепочки `next()` (играют параллельно).
   Встречается только при быстром переключении выключателя; не трогал.
5. **Мелко (спорно)** — engine.ts:272: лечение героя ограничено `s.heroHp` (30), а второй игрок стартует с 34: пока он выше 30, лечение впустую.
   Правила про это молчат; считаю допустимым.
6. **Мелко** — view.ts подсветка руки (`ok`) не учитывает `canPlay` для приёмов без цели («всем своим» при пустой лавочке): клик отправит ход,
   движок его отклонит, выбор сбросится. Зависаний нет.

## Проверено и выглядит надёжно

- **Скрытая информация.** `view` отдаёт чужую руку как `null`, колоды — только счётчиком; `redact` скрывает `id` чужого добора (сгоревший из-за полной
  руки виден всем намеренно), зрители (seats = []) видят всё как чужие. Бот работает через `stateFromView` (чужая рука — пустые строки), симуляции с
  неизвестной картой ловятся `try/catch` в `step`.
- **Движок.** Рывок/сон, Стенка (прикрывает героя и соседей, но не от приёмов — осознанно), Броня, Пара, ответный удар одновременно, оглушение
  (done на старте хода), цепочка «Прощаний» (guard 10), усталость, предел 80 ходов (по терпению, ничья при равенстве), обе стороны мертвы -> ничья,
  лечение не выше максимума, цели приёмов проверяются по списку `fxTargets`; `apply` не мутирует исходное состояние.
- **Зависания.** `toAct` пуст только при `over`; `end` всегда допустим; бот выбирает из `legal()`; хард-бот конечен (каждое действие тратит карту/удар).
- **Коллекция и правило про рубли.** `openGum`: купленные монеты тратятся первыми, при любой купленной монете вкладыши домашние (`h`);
  `checkYard`/`moveYard` учитывают только дворовые (`y`), домашние не ставятся и не меняются; `dustExtras` сначала сдаёт домашние за купленные монеты;
  `free()` вычитает отложенные. Серверные начисления/кон — по отдельной проверке.
- **view/home.** Слушатели `resize`/`keydown`/ResizeObserver и музыка освобождаются в `destroy`; опросы обмена/кона (`setInterval`) снимаются при закрытии окна.
  Награда за партию запрашивается один раз и только офлайн (`!ctx.online`), лимит — на сервере.
