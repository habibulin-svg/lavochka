# Глубокое ревью: «Корона» и «Детектив»

## Находки

### Детектив
1. **Важно, исправлено.** `detektiv/engine.ts` `view()`: в «Сыщике» у чужой доски уходили `wrongs` (зачёркнутые версии) — у всех один список дел, так видно, какие версии неверны. Теперь `wrongs: []` для чужих досок.
2. **Важно, исправлено.** `detektiv/engine.ts` `redact()` возвращал событие как есть: события `wrong` (номер версии) и `free` (текст свободного ответа) в «Сыщике» и «Кто быстрее» уходили всем. Теперь события несут `hide`, `redact` обнуляет `k = -1` / `text = ''` для чужих мест и зрителей; в бригаде открыто. `def.ts` `describe` умеет такие события.
3. **Важно, исправлено.** `detektiv/def.ts` бот: в бригаде бот нажимал «дальше» сразу после закрытия дела — людям не давал прочитать разгадку. Добавлен `Board.t1` (когда закрыто), бот ждёт ~6 с (в тестах без пауз — по счётчику «думаю»).
4. **Спорно, не трогал.** Ключ (`data/key.ts`, ~590 КБ с верными версиями и разгадками) импортируется движком, а движок — `def.ts`/`view.ts`, поэтому весь ключ едет в клиентский бандл. Любой, кто откроет код страницы, прочитает все ответы заранее. Починка — крупная: вынести ключ в отдельный модуль только для хоста/сервера, а клиенту отдавать только то, что в `view`. Но в P2P/локальном режиме хост-браузер всё равно держит движок. В серверных комнатах и по `view` до закрытия дела разгадка не уходит (проверено, тест есть).
5. **Спорно.** Бот берёт верный ответ прямо из `keyOf` (а не из `view`) — задумано («детектив такого-то класса»), для сети с ботами не утечка.
6. **Спорно.** «Уже читал» (`swap`) одного игрока в «Сыщике» сбрасывает дело (наводки, ошибки, таймер) у других, кто сидит на том же деле. По замыслу «заменить дело за столом».

Вопрос «Верхняя карта: №N «…» — текст» (Звездочёт, Эльф, Детектив, шпион) показывался строкой статуса всем за столом (`classic/view.ts` `status`) — подсматривание колоды видели все.
