# Глубокое ревью: «Шахматный кружок» (kruzhok)

Особенность: это аркадный модуль (`ArcadeModule`), без `def.ts`/`view`/`redact` и без скрытой информации; ботов нет (движок — Stockfish в Worker). Разделы 1–4 из инструкции к нему не применимы, главное — view-логика, рейтинг, прогресс, воркер.

## Находки

1. **trainer.ts:~252 — важно, исправлено.** После верного хода соперник отвечает через 600 мс, кнопки «Показать решение»/«Подсказка» оставались живыми. Нажатие «Показать решение» в это окно запускало цикл решения параллельно с `opponent()`: цикл потом играл устаревший ход на уже изменённой позиции (разъезд `ply`/позиции). Починка: `buttons([])` на время ответа соперника.
2. **etyudy.ts:~290 — важно, исправлено.** Ход ученика, не совпавший с авторским, но ставящий мат (в этюдах «мат в N» и «выигрыш»), считался «выигрыша уже нет»: у матованной позиции у Stockfish нет линий, `v = 0`. Теперь мат, поставленный `checkMark`, засчитывается как «тоже держит результат».
3. **storm.ts:~248 — мелко, исправлено.** После штрафа −10 с время уходило в минус, но штурм завершался только на следующем тике — ещё секунду можно было решать. Теперь `stop()` сразу.
4. **analysis.ts:~189 — важно, исправлено.** Ввод FEN проверял только наличие королей, а не ровно по одному у каждой стороны; позиция с несколькими королями уходит в Stockfish (вылет воркера/зависание). Теперь требуется ровно один K и один k.
5. **analysis.ts:~108 — мелко, исправлено.** Комментарий обещал «тот же ход, что дальше по записи, — идём вперёд», а код всегда обрезал остаток партии. Теперь при совпадении позиции переходим на следующий ход без обрезки.
6. **route-ui.ts:~99 — мелко, исправлено.** Если разбор партий (`reviewPending`) падал (движок не запустился/прерван), `ask()` давал необработанное отклонение и «Михалыч разбирает…» зависало. Теперь ловим и строим маршрут по уже разобранному.
7. **journal.ts:~81 — мелко, исправлено.** «Начать журнал заново» не сбрасывало `kruzhok.mated` (доигранные до мата партии): звёзды за них после сброса были бы недоступны.

Спорно / не трогал:
- **lessons.ts:356, 267, 306** — звёзды за верный ход шага урока (+2 и т.п.) начисляются на каждом заходе в шаг (`solved/missed` сбрасываются в `show`), можно крутить prev/next и набирать звёзды. Только локальный счёт «звёзд» (не рейтинг, не деньги). Починка потребует хранения «шаг уже оплачен» в журнале — не трогал.
- **trainer.ts, задача дня** — задача выбирается из всех, включая решённые; решённая повторно в тот же день даёт +3 за «задачу решена» (рейтинг не меняется: `first=false`). Мелочь.
- **chess/stockfish.ts:55–68 (вне папки игры, не трогал)** — таймер 25 с `slow` из `boot()` после `quit()` при быстром повторном входе может в `fail()` терминировать уже новый воркер (`this.w` общий). Узкий случай (выйти и войти в кружок за <25 с во время загрузки движка, без `readyok`).
- **cloud.ts** — синхронизация «кто новее, тот целиком побеждает» (LWW по всему журналу): прогресс с двух устройств без захода между ними теряется. Осознанное решение дизайна.
- Разряд: `FIRST_RANK_AFTER` считает и задачи с ошибкой (`solved[id]=0`) — «решал», а не «решил»; по тексту допустимо.

## Проверено и выглядит надёжно

- **Проверка решений задач:** принимается ход из записи ИЛИ любой ход, ставящий мат (`checkMark === '#'`) — на любом шаге, в «Задачах» и «Штурме»; последний ход решения — завершение; ход, не совпавший, но не мат — «не то» + опровержение Stockfish (Lichess-подход). Промоции в `toUci` с буквой.
- **Рейтинг:** `update` — корректный Глико (g, E, d², RD'=√k), RD растёт за простой, зажим 400…3000 и RD≥60, NaN не возникает (тест). Меняется только за первую попытку (`first`), подсказка/уход с задачи/ошибка — `fail()` до решения; перезагрузка с открытой задачей — `OPEN` записывает провал.
- **Повтор ошибок:** сроки 1/3/7 дней, три верных повтора подряд убирают из очереди, ошибка на повторе — сбрасывает (тест).
- **Сохранение прогресса:** все записи через `store`+`touch()`, `loadProgress` объединяет с `fresh()`; сервер `/api/kruzhok` не принимает денег/начислений, только журнал владельца (старее записанного не пишется).
- **Stockfish-воркер:** единственный синглтон на страницу (`boot` кэширует `ready`), не плодится; `quit()` в `destroy` модуля терминирует воркер и отклоняет текущую задачу; каждый подраздел в `destroy` делает `stop()`; ожидания (`sleep`) защищены `gen/run/alive`.
- **view-утечки:** слушатели `keydown` снимаются в `destroy` (lessons, partii, analysis); таймер штурма — `clearInterval`; `Board.destroy`, `mh.destroy`, `host/el.remove` везде; `pagehide` в cloud — один глобальный.
- **Партии мастеров:** ответы пишутся один раз на остановку, узел пути закрывается по всем отвеченным; «доиграй сам» защищён `token/fightRun`.
- Скрытая информация, боты, сетевой стол: не применимо.

Проверка: `npx tsc --noEmit -p .` чисто; `GAMES_ONLY=kruzhok npx vitest run tests/games-[1-8].test.ts tests/kruzhok*.test.ts` — 13 файлов, 808 тестов зелёные.

Изменено: trainer.ts, etyudy.ts, storm.ts, analysis.ts, route-ui.ts, journal.ts; новый тест tests/kruzhok-deep.test.ts (мат-альтернатива, рейтинг/повтор ошибок, границы Глико).
