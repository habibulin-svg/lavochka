# Пачка 07

Код-ревью без правок кода. Проверено: `def.ts`, движок, `ai.ts`, `view.ts`, сверка правил с числами движка. Некоторые игры (basketball, shagdy, hive, konversiya, skyruk внутри ur) проверены выборочно — это отмечено в разделах.

## viktorina
- **важно** `src/games/viktorina/engine.ts:1202` и `:1214` (`pressAt` в `engine.ts:397`) — время нажатия/ответа человека берётся из `a.at` клиента с ограничением только сверху (`Math.min(s.now, at)`), без нижней границы. Сценарий: клиент шлёт `at` = `openAt` на каждый ответ — в «Кнопке» всегда выигрывает первое нажатие, в тривиа по сети получает максимум +100 за быстроту и +50 первому верному. Починка: ограничить `at` окном `[s.now − MAX_LAG, s.now]` (MAX_LAG ~1–1,5 с, по измеренному пингу комнаты), а не `[openAt, now]`.
- **мелочь** `src/games/viktorina/def.ts:510` — текст «ровно половина правдивы, половина нет», а `engine.ts:383` (`truthQ`) решает каждый вопрос монеткой `rng.next() < 0.5`. Сценарий: в партии из 10 утверждений может быть 7 правдивых. Починка: заранее перемешать список с ровно половиной верных либо поправить текст на «примерно половина».
- **мелочь** `src/games/viktorina/def.ts` (раздел «Барабан», `Приз`) — движок начисляет за букву «Приза» `100 × n` очков (`engine.ts:1275`), текст правил про очки за приз молчит. Починка: дописать в правила «Приз — ещё 100 за каждую открытую букву» либо убрать начисление.
- замечаний по утечкам нет: `view` прячет варианты при `showOpts=false`, `q.ok` и `know` идут только боту (`engine.ts:1520–1527`), `answered` без варианта до показа, `stamp` сервера перезаписывает `now`/`win`.

## konversiya

## basketball
- замечаний нет (выборочно). `snapshot` (`engine.ts:552`) округляет физику, скрытого состояния (rng, будущие броски) в `BbState` нет: бросок разыгрывается в момент `launch`. Таймеры (`view.ts:216`, `:295`) безвредны после `destroy`; RAF и `Court3D.dispose()` освобождаются (`view.ts:314–317`, `scene.ts:564`). Физику и правила очков не разбирал.

## shariki
- **важно (не уверен)** `src/games/shariki/versus.ts:320` — в общем снимке `snapshot` для всех мест отдаётся `next: z.next` (следующий шар каждого игрока). Сценарий: соперник видит, какой шар у тебя в «готовности», и заранее выбирает свой ход. Починка: если следующий шар должен быть скрыт — отдавать его только владельцу (снимок по местам), остальным `next: -1`. Если открытость намеренная — пометить в правилах.
- **мелочь** `src/games/shariki/index.ts:171` — `setTimeout(() => this.finish(), 600)` не отменяется в `destroy()` (`index.ts:243–248`). Сценарий: игрок уходит со стола в течение 600 мс после победы — `finish` срабатывает уже после ухода. Починка: сохранить id таймера и `clearTimeout` в `destroy`.
- `netview.ts` освобождает RAF, `keydown` и `setInterval` через `cleanup` (`netview.ts:487–491`) — замечаний нет.

## hive
- замечаний нет (выборочно). Королева к 4-му ходу: `placeBugs` (`engine.ts:321`) и турнирный запрет первым ходом (`engine.ts:322`) совпадают с текстом `def.ts:100`. Связность улья: `pinned` (`engine.ts:144–170`) — точки сочленения Тарьяна, отдельно учтены стопки высотой > 1. Ходы без королевы запрещены (`engine.ts:335`). Скрытой информации нет (руки открыты по правилам игры). `view.ts` без глобальных слушателей.

## azul
- **мелочь** `src/games/azul/engine.ts:186–193` (`toFloor`) и `:329` — мастерок, который не влез на пол (уже 7 плиток), молча пропадает: пенальти −1 не начисляется, а первый игрок всё равно переходит (`s.next = seat`). Починка: либо явно считать пенальти за мастерок отдельно, либо запретить взятие мастерка при полном полу (по правилам мастерок занимает место на полу).
- **мелочь (не уверен)** `src/games/azul/def.ts:78` — `view: s => s` отдаёт счётчики мешка `bag` и коробки `box`. Порядок плиток не раскрыт (`draw` берёт `rng.int` по счётчикам), так что это уровень, который и так видно по опыту игры. Пометка, а не ошибка.
- подсчёт очков (`tilePoints`, `floorScore` с `Math.max(0, …)`), бонусы (`bonus`), ничья по полным рядам (`finish`) и числа фабрик (`factoriesFor` 5/7/9) совпадают с текстом правил.

## canasta
- замечаний нет. `makeView` (`engine.ts:421–430`) убирает `stock` и руки чужих мест; `redact` (`def.ts:36–41`) прячет `cards` у чужого `draw` и руки в `deal`; `pile` публичен по правилам. Проверены: `validMeld` (натуральных ≥ 2, диких < натуральных и ≤ 3), `minMeld` 15/50/90/120, очки карт и канаст 500/300, красная тройка (100/800, в минус без выкладки), `canTakePile` для замороженной кучи, выход только при нужном числе канаст (`engine.ts:367`). Текст «выход +200 при выкладке одним ходом» соответствует `laid`.

## cenariska
- **критично** `src/games/cenariska/engine.ts:186` и `src/games/cenariska/def.ts:76` (нет `redact`). Событие `draw` несёт `tile: s.hand` всем местам. Сценарий: по правилам тайл вытягивают «вслепую», но соперник получает его вид сразу после вытягивания и до сдвига. Починка: в `redact` для `draw` убирать `tile` для всех, кроме вытянувшего (`ev.seat`), и открывать его вид уже событием сдвига, которое делает игрок.
- **важно** `src/games/cenariska/def.ts:76` (`view: s => s`) и `engine.ts:127` (`stock: Kind[]`). Клиент получает весь закрытый запас с составом оставшихся тайлов, а `hand` (вытянутый тайл) — всем. Сценарий: по `state.stock` и `state.hand` соперник точно знает, какие тайлы остались. Починка: `view(s, seats)`: `stock: []` + `stockLeft`, `hand` — только вытянувшему месту.
- `ai.ts` `stock` не использует, UI `view.ts` тоже; проблема только в передаваемых данных.

## shagdy

Конец круга (`endTurn`, `engine.ts:282–306`): «первый дошёл — второй доигрывает круг», ничья при одновременном выходе, сравнение прогресса при исчерпании сочетаний — логика согласована с описанием в шапке `engine.ts`. Бот (`ai.ts`) использует `choose` с полным `s`, но без скрытых данных. Детальную сверку правил со статьёй (`docs/analysis/shagdy.md`) не делал.

## g2048
- замечаний нет. `slide` (`engine.ts:`, `slide()`) не даёт сложиться одной плитке дважды за ход (`lastMerge`), камни режут линии, `canMove` корректен. Отмена хода (`undo`) выключена в гонке и после конца партии. Номера плиток уникальны между досками (`bi·10⁶`). Бот (`bot.ts`) считает только по своей доске (`boardOf`). В гонке `view` отдаёт все доски — это не скрытая информация.

## drunkard
- **важно (не уверен)** `src/games/drunkard/view.ts:129` — галочка «авто» переворачивает карту человека сама (`kick` → `flip` через `setTimeout`). Сценарий: игрок включил «авто» и не принимает решений, а ход делает таймер. Правило «игры не играют сами в себя» делает такую опцию спорной. Починка: убрать «авто» либо явно оформить как режим бота за человека (с пометкой в интерфейсе).
- таймер `autoTimer` очищается в `destroy` (`view.ts:224`) — ок.
- скрытая информация: `makeView` (`engine.ts:188–196`) прячет порядок стопок и рубашки стола, `redact` (`def.ts:33–37`) прячет подкладку; `counts` публичны. Спор, жребий при пустых руках, лимит `HARD_LIMIT` (1500) и победа по числу карт при `dark` — без замечаний.
