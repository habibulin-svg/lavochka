# Пачка 02
Охват: def.ts, движки, ai/bot, view-функции, destroy/таймеры. Крупные игры (hodilki, brick2026) смотрены выборочно — см. примечания.

## hodilki
- **важно** `src/games/hodilki/def.ts:271` — ответ на загадку: `solved = a.correct === true || …`. Флаг `correct` задуман для бота («бот называет свою удачу»), но сервер принимает его и от человека. Сценарий: игрок, отвечающий на загадку, шлёт `{type:'answer', correct:true}` без ответа — засчитывается как отгадка, загадавший лишается награды. Починка: доверять `correct` только для ботов (seat — бот по `bots`/состоянию комнаты), для людей — только сверка текста с `riddle.answer`.
- **мелочь** `src/games/hodilki/view.ts:779` — `requestAnimationFrame(() => this.updateTiles(...))` в `queueTiles` не отменяется в `destroy` (`view.ts:1520`). Сценарий: выход со стола во время очереди кадра — колбэк работает над уже удалённым DOM. Починка: хранить id кадра и отменять в `destroy`.
- Не находка (по задумке): `view.ts:1509` показывает карточки «Шёл солдат» всех игроков поимённо — в комментарии прямо сказано «видны поимённо».
- Примечание: не проверено целиком — `view.ts` (77 КБ), `core.ts` кроме `walkFor`, данные полей (`kosmos`, `krugosvet`, `luk`, `shel`, `nastolki`, `put`, `vput`, `shayba`). Логика хода (бросок → ручной перенос, развилки, загадки, гонка) проверена.

## loto
- **важно** (не уверен) `src/games/loto/engine.ts:428-431` — `makeView` отдаёт `answers` всем игрокам до того, как ответили все (в «Вокруг света» — номер выбранной картинки). `view.ts:214` показывает наружу только ✋/✓, но данные содержат номер. Сценарий: тот, кто отвечает позже, видит в `view`, какую картинку выбрал предыдущий, и может скопировать ответ. Починка: пока раунд не закрыт, отдавать чужие ответы без номера (`answers` только для своего места и факт ответа списком), полный набор — после `answers` сброса.
- Не находка: видимость чужих карточек (`engine.ts:429`) задумана — в шапке `view.ts` сказано «чужие карточки — мельче».
- Замечаний по правилам русского лото (бочонки, призы, «нет у меня», пропуск) нет.

## saper
- **критично** `src/games/saper/engine.ts:339-341` — в «Наперегонки» поле проигравшего (`st = 'lost'`) отдаётся всем целиком: условие скрытия стоит только для `!over`, а `over` истинно для любого проигравшего поля. Раскладка мин общая на все поля (`engine.ts` `setup`, режим race), значит, тот, у кого поле ещё в игре, получает полную карту мин соперника и выигрывает без риска. Сценарий: Вася подорвался на 3-м ходу; у Пети в `view` его поле с `mine` и `num`; Петя открывает только безопасные клетки. Починка: в `view` для race скрывать чужие поля, пока `s.done` не наступил; раскрывать чужие поля только при `s.done`.
- **мелочь** `src/games/saper/view.ts:104-107` — `destroy()` чистит только интервал и `ResizeObserver`; таймер долгого нажатия (`view.ts:258`, `window.setTimeout`) не сбрасывается. Сценарий: уход со стола при зажатой кнопке — через 420 мс сработает `draw()` на удалённом виде. Починка: в `destroy` вызвать `cancelPress(false)`.
- Бот (`bot.ts`) смотрит только на свой `view` и выводы по открытым числам — ок.

## pinochle
- **критично** `src/games/pinochle/def.ts:42-49` (функция `redact`) и `src/games/pinochle/engine.ts:247-248` — при заказе втроём событие `won` несёт `widow` (три закрытые карты прикупа), а `redact` его не режет (нет ветки для `won`). Описание в журнале (`def.ts:26`) печатает прикуп всем. Сценарий: втроём Джо берёт заказ — все трое видят его прикуп. Починка: в `redact` добавить `if (ev.type === 'won' && ev.widow && !seats.includes(ev.seat)) return { ...ev, widow: undefined };` (для `seats === 'all'` не менять).
- Остальное проверено: торги (спасовавший выходит, все спасовали → сдатчик 250), мелды (ран, марьяжи, дикс, тузы/короли/дамы/вальты, пинокль), обмен с напарником (`pass`/`return`), подсчёт (заказ не сыгран → минус заказ, мелды только при взятке, последняя взятка +10), вдвоём (колода, открытый козырь у сдатчика, мелд после взятки, строгий ход после колоды).

## xiangqi
