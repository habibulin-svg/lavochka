# План переделки сайта «Вечером на лавочке» (2026-10-18)

ТЗ пользователя от 2026-10-18: адреса и «назад» браузера, SEO-лендинги игр и пресетов, поиск, сервисы в духе 2000-х (чат, форум, новости, блог), лобби с постоянными комнатами, турниры, роли и модерация, команды по согласию, три уровня доступа и подписка, сортировка игр, статистика, админка, роль Мастера.

Продвижение на первом этапе — **только SEO**, поэтому порядок работ подчинён ему: сначала то, что индексируется и копит возраст (адреса, страницы, тексты), потом то, что держит пользователя (аккаунты, лобби), потом то, что монетизирует (подписка).

## Что есть сейчас

- Одностраничник: `main.ts` → двор (`launcher/yard.ts`) → экран игры (`core/home.ts`) → стол (`core/table.ts`). Адрес не меняется, «назад» уводит с сайта. `nav.home/yard` в `session.ts` — внутренняя навигация без History API.
- Сервер `server/index.ts` (Node, `ws`): раздаёт `dist/`, комнаты по коду (`/ws`), рекорды (`/api/records`), TURN (`/api/ice`). Состояние — в памяти и JSON-файле, базы нет. Хостинг — Render.
- Каталог `games/catalog.ts`: ~70 карточек, у игр `presets` с `id/label/hint` — готовое сырьё для страниц вариантов.

## Сквозные решения

### Адреса
- Игры — коротко, в корне, транслитом: `/nardy/`, вариант — `/nardy/dlinnye/`, поле кинь-двинь — `/kin-dvin/lukomorye-1/`, игра «Электроники» — `/elektronika/nu-pogodi/`. Короткий адрес с ключом лучше `/games/12`.
- Разделы — тоже в корне, русским транслитом: `/novosti/`, `/blog/`, `/forum/`, `/chat/`, `/lobbi/`, `/turniry/`, `/poisk/`, `/vhod/`, `/profil/`, `/admin/`. Список занятых слов — в одном месте; тест проверяет, что slug игры с ним не пересекается.
- Стол — `/stol/<код>` (сетевая партия, `noindex`); локальная партия — тот же адрес варианта с `?igra` (`noindex`, canonical на вариант). «Назад» со стола → экран игры → двор: каждый экран — запись в истории (`pushState`), `popstate` возвращает на прошлый экран.
- Отдельная страница варианта — **только там, где у него есть свой спрос** в Wordstat («длинные нарды», «косынка», «переводной дурак»). Варианты без спроса — раздел на странице игры, без своего адреса: пустые однотипные страницы Яндекс считает малополезными и понижает весь сайт.
- Все три домена → 301 на основной `lavochka-games.ru`, `www` → без `www`, слэш в конце — единообразно; старый адрес на Render → 301 на новый.

### SEO-страницы (пререндер)
- При сборке скрипт генерирует **готовый HTML** для каждой игры/варианта/статьи (`dist/nardy/dlinnye/index.html`): `title`, `description`, `h1`, текст, правила, FAQ, скриншоты, хлебные крошки, `canonical`, Open Graph, schema.org (`VideoGame` + `FAQPage` + `BreadcrumbList`). Поисковик видит содержимое без JS; JS поверх монтирует игру. nginx раздаёт эти файлы напрямую — сервер не нагружается.
- Источник текстов — `src/games/<id>/seo.ts` (без DOM, как `def.ts`): на игру и на каждый вариант с адресом — заголовки, описание, вводный текст, «чем отличается», FAQ, ключевые фразы. Правила уже есть в `def.rules` — рендерятся в HTML и дают уникальный объёмный текст бесплатно.
- Скриншоты — тот же конвейер `showcase` → `?thumb=`, но на вариант (`?thumb=nardy&preset=short`): переключил пресет — новые текст и картинка.
- Страница игры = лендинг: крупная кнопка «Играть» (с ботом / с друзьями по ссылке / в лобби) **на первом экране**, ниже — варианты, правила, FAQ, похожие игры (перелинковка), свежие статьи блога по игре.
- `sitemap.xml` (генерируется), `robots.txt`, Яндекс.Вебмастер и Google Search Console, IndexNow при выкладке, Метрика с Вебвизором. Скорость: картинки webp/avif, ленивые модули игр — уже так.

### Поиск
- Индекс строится при сборке из каталога: игры, варианты, поля кинь-двинь, игры «Электроники» и автоматов, синонимы и народные названия («косынка», «очко/21», «козёл в домино», «тысяча/1000»), частые запросы из Wordstat.
- Работает в браузере, без сервера: нечёткое совпадение, исправление раскладки (`ylfhls` → «нарды»), транслит. Один результат → сразу экран игры с выбранным вариантом; несколько → карточки (у каждой — свой вариант). Адрес `/poisk/?q=` (`noindex`).

### Данные и сервер
- PostgreSQL на том же VPS (FirstVDS, 2 ГБ). Сервер Node остаётся один: `/ws` (комнаты, лобби, чат), `/api/*` (аккаунты, лобби, турниры, новости, статистика, админка). Схема миграциями в репозитории; ночной `pg_dump` во внешнее хранилище.
- Комнаты и турниры переживают перезапуск сервера: состояние лобби — в базе, идущая партия — снимок в базе раз в ход (сейчас — только в памяти).

### Доступ и роли
- Уровни: **гость** (все игры, игра по коду), **игрок** (регистрация: сохранения, лобби, лайки, история партий), **подписчик** (голос/видео, ранний доступ, AI-функции), **Мастер** (всё + админка).
- Не «уровень = набор кнопок», а **права (entitlements)** с датой окончания: `voice`, `video`, `early_access`, `ai`, `lobby_host`, … Подписка выдаёт набор прав на срок; Мастер вручную выдаёт любые права любому пользователю или группе на любой срок. Клиент получает список прав при входе, сервер проверяет их сам (голос/видео — при выдаче TURN и сигнализации).
- Ранний доступ: у игры в каталоге `access: 'early'` + дата публичного выхода — до неё карточка видна всем с замком «для подписчиков», страница индексируется, играть могут только с правом `early_access`.
- Вход: почта + пароль (argon2), сессия в httpOnly-cookie; позже — VK ID и Яндекс ID (в РФ это главный способ быстрой регистрации). Почта для подтверждения и сброса — через SMTP-сервис (Unisender/Яндекс 360).
- 152-ФЗ: данные на сервере в РФ (уже), политика конфиденциальности и согласие при регистрации, уведомление РКН как оператора ПДн — до открытия регистрации.

### Лобби и постоянные комнаты
- Сейчас «комната» = одна партия по коду. Нужна обёртка — **стол (комната лобби)**, внутри которого живут партии: выбрать другую игру, сменить пресет, начать заново, встать/сесть — всё по общим правилам комнаты. Нынешний `Room` становится «партией» внутри стола; код партий не меняется.
- Свойства стола: создатель, админы, видимость (в списке / только по ссылке), пароль, лимит мест, наблюдатели, чат, голос.
- Роли и модерация: создатель → админы → игроки → зрители. Кик, бан (стол/сайт, на срок), предупреждения, мут в чате, передача прав. Сайтовые модераторы и Мастер видят жалобы.
- «Хочу сыграть»: заявка на несколько игр/вариантов сразу; лобби сводит заявки и предлагает стол. Вход в лобби — с карточки любой игры (фильтр по ней) и из шапки.
- **Команды по согласию**: в парных играх (козёл, бридж, дурак 2×2, домино 2×2…) — «позвать в напарники» → напарник подтверждает; на экране игры и в столе лобби. В 3D-холдеме — выбор аватара.

### Турниры
- Форматы: олимпийка, двойное выбывание, круговой, швейцарка; одна игра или серия игр.
- Жизненный цикл: анонс → регистрация → check-in → туры по расписанию (сервер сам создаёт столы и рассаживает) → результаты из партий сервера (без ручного ввода) → сетка/таблица → итог. Ведущий: замена, техническое поражение, перенос, дисквалификация.
- Страницы турниров индексируются (`/turniry/<slug>/`) — тоже SEO-контент.

### Разделы и шапка
- Новости и блог — записи в базе, редактор в админке (Markdown + картинки), пререндер страниц при публикации (сервер сам пишет HTML в папку, nginx раздаёт). Блог — главный SEO-источник длинного хвоста: «правила игры в храп», «как играть в длинные нарды», «советские настольные игры 90-х».
- Чат с комнатами («Двор», «Карточный стол», «Флудилка» …) — на той же WebSocket-связи, что и лобби.
- Форум — последним и только если будет живое сообщество; до этого — комментарии под статьями и обсуждение в чате. Свой простой, не phpBB: один логин и одна стилистика.
- Шапка в духе 2000-х: узкая полоса-«баннер» с логотипом и счётчиком онлайна, под ней ряд кнопок-вкладок (Игры · Лобби · Турниры · Чат · Новости · Блог · Форум) и справа вход/профиль. На телефоне — логотип, поиск, кнопка «меню» с теми же вкладками крупным списком; профиль — значком. Эскизы — отдельным шагом до вёрстки.
- Сортировка на главной: как сейчас / по числу сыгранных партий / по лайкам / по новизне (в каталог — `added: '2026-03-14'`, счётчики — с сервера, кэш на минуту).

### Статистика и админка
- Внешняя — Яндекс.Метрика (посещаемость, источники, поисковые фразы, цели «начал партию», «зарегистрировался», «оформил подписку»).
- Своя — таблица событий в Postgres: партия начата/закончена (игра, вариант, боты/люди, длительность), онлайн, столы, турниры, регистрации, подписки, трафик TURN. Сводки по дням.
- Админка `/admin/` (только Мастер и выданные права): дашборд, пользователи и группы, выдача прав на срок, баны, жалобы, новости/блог, турниры, игры (видимость, ранний доступ, порядок, «новинка»), SEO-тексты страниц, статистика. Новые **игры** по-прежнему приходят кодом и деплоем; админка управляет их выходом (скрыта → ранний доступ → для всех).
- Мастер — пользователь с правом `master`, логин/пароль + обязательный второй фактор (TOTP), заводится командой на сервере, а не через сайт.
