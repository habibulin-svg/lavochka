## 1. Где лежит

`lavochka/src/gops/` — отдельное полноэкранное приложение в репозитории сборника (общие сервер, `core/audio`, комнаты и голос — потом).

```
src/gops/
  sim/            детерминированная логика: БЕЗ DOM, БЕЗ float в состоянии, БЕЗ Math.random/Date
    fx.ts         фиксированная точка Q8, целочисленные sin/cos/atan2/isqrt
    rng.ts        mulberry32 (тот же, что в studio/post/terrain.py)
    mask.ts       битмап ландшафта: твёрдо/воздух, вырезать/добавить круг, лучи, нормаль, связность
    terrain/      генератор ландшафта по рецепту уровня (перенос studio/post/terrain.py)
    world.ts      состояние мира и шаг step(world, input)
    body.ts       физика тел (точка/круг против маски), отскок, покой
    worm.ts       боец: ходьба по склону, прыжок, сальто, падение, урон от падения, прицел
    weapons/      оружие: таблица + поведение снарядов
    turn.ts       ход: ящики → ход (таймер) → отход → ждём покоя → урон/выбывшие → следующая бригада
    input.ts      ввод одного кадра (лок-степ по сети)
    hash.ts       хеш мира (сверка клиентов)
  bot/            боты: перебор выстрелов на копии мира тем же sim
  render/         PixiJS v8: ландшафт (текстура темы × маска), камера, спрайты из атласов, эффекты, жидкость
  ui/             DOM поверх холста: HUD, сетка оружия, меню, экраны, ролики
  data/           таблицы оружия, загрузка missions.json и текстов
  net/            лок-степ поверх core/realtime (этап 3)
  main.ts         вход приложения
```

Тесты — `lavochka/tests/gops/*.test.ts`.

## 2. Правила sim (детерминизм)

Один и тот же сид + один и тот же поток ввода → бит в бит один и тот же мир на любом браузере. Отсюда:

- **Числа в состоянии — только целые.** Координаты и скорости — Q8 (1/256 пикселя) в обычных `number`, все операции заканчиваются `| 0` или `Math.trunc`/`>>`. Деление — через `fdiv` из `fx.ts` (усечение к нулю).
- **Никаких `Math.sin/cos/atan2/sqrt/pow/exp`** в sim — только таблицы и целочисленные функции `fx.ts`. Углы — в 1/4096 оборота (`ANG_FULL = 4096`).
- **Случайность — только `Rng` из `rng.ts`**, состояние rng — часть мира.
- **Порядок обхода фиксирован:** массивы, не `Map`/`Set` с порядком вставки от случайных событий; сортировки — стабильные по id.
- Шаг — фиксированный 60 Гц (`TICK_HZ`). Рендер интерполирует, sim не знает о времени кадра.
- sim отдаёт **события** кадра (взрыв, всплеск, звук, урон, выбыл) — рендер и звук берут эффекты оттуда, а положение тел — из состояния.
- Тест `tests/gops/sim-rules.test.ts` проверяет исходники sim на запрещённое (`Math.sin`, `Math.random`, `Date`, `performance`, `document`, `window`).

## 3. Масштабы

| Что | Значение |
|---|---|
| Карта | 1920 × 704 логических px (как `terrain.py`), маска `Uint8Array` W·H, 1 = земля |
| Боец | хитбокс-круг r = 9 px, рост спрайта ~48 px на экране |
| Гравитация | 0,15 px/кадр² (подбирается) |
| ХП | 100 по умолчанию (схема/миссия меняет) |
| Ход | 45 с, отход 3 с (схема) |

## 4. Принятые решения (2026-11-01)

- **Маски кампании не генерируются в браузере:** `studio/post/export_levels.py` (из `terrain.py`) → `public/gops/levels/<id>.json` (RLE, 1,3 МБ на 66 уровней) + `missions-index.json`. В сети хост шлёт маску — расхождение браузеров на `Math.sin` исключено. TS-перенос генератора нужен только «Пустырю» (задание для 27B, сверка с масками Python).
- **Внезапная смерть** — после `roundTime` (600 с времени ходов) жидкость поднимается каждый ход на `riseStep`.
- **Утонувший кепки не оставляет**, сдувшийся на земле — оставляет (`world.caps`).
- **Застрявший в углу** (не сдвинулся 8 кадров при касании) — встаёт.
- **Бот** (`bot/bot.ts`) — у хоста, может считать во float; полёт — тем же `stepBody` по маске без копии мира; 21/59/166 мс на обдумывание (лёгкий/средний/сложный). Нет выгодного выстрела — идёт к ближайшему врагу и думает заново.
- **Ассеты в разработке** — прямо из `G:/temp/studio/out/gops` (`src/gops/assets.ts`, `/@fs/`); после отбора — `public/gops/`.
- Страница — `gops.html` (второй вход Vite). Разработка: `/gops.html?level=m03&vs=medium&n=3`, бой ботов — `&p1=hard&vs=hard`.

11. ✅ **Быстрый бой и сеть (2026-11-02).** Экран быстрого боя: 2–4 бригады, люди и боты (за одним экраном), карта, арсенал, здоровье, время хода, ветер, внезапная смерть, ящики; баннер «Ходит …». **Сеть — лок-степ через ретранслятор:** `server/gops.ts` + `src/gops/net/relay.ts` (сервер физику не считает: часы 60 кадров/с, номер кадра на ввод мест — удерживаемое + одно разовое на кадр, рассылка пачками раз в 50 мс; ввод чужой бригады не принимает), клиент `net/client.ts`, `Game.netPump` шагает ровно по пришедшим кадрам. Боты — в каждом браузере одинаково (rng от сида). Сверка `worldHash` в начале каждого хода, расхождение — «рассинхрон», партия стоп. Меню «По сети»: имя, новая комната (та же настройка + «сетевой игрок»/«за моим экраном»), вход по коду, лобби (код, кто за какой бригадой, «Сесть»/«Встать», «Начать» у хозяина). Проверено двумя вкладками через `lavochka-server`. **Возврат после обрыва:** сервер хранит журнал кадров; вернувшийся по тому же имени садится за свою бригаду и догоняет мир (порциями по 3000 кадров), новенький — смотрит; начатая партия ждёт пустой две минуты. **Чат и голос:** `ui/talk.ts` — строки чата слева (T — написать), 🎤 — голос через `core/voice.ts` (переходник: NetClient отвечает id/on/voice/rtc, сигналы WebRTC пересылает ретранслятор только между теми, кто в голосе; без камеры). Голос вживую не проверен (нет микрофона в панели браузера). **Восстановление после рассинхрона:** сервер стопит часы, досылает кадры и просит снимок мира у хозяина (`sim/snapshot.ts`: маска сериями в base64 + поля мира), снимок идёт частями по 40 000 знаков (предел сообщения 64 КБ), остальные накладывают его на свой мир, у всех боты заново от сида и кадра, часы — с того же кадра. Проверено вживую порчей мира гостя.
