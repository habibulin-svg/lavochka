# Вечером на лавочке

Сборник дворовых игр в браузере. Лаунчер — вечерний двор 90-х, у каждой игры есть боты с уровнями сложности,
сетевая игра по коду комнаты и правила с наглядным показом на настоящем поле.

Сейчас готов **Шиш-беш**, остальные игры в каталоге отмечены «скоро» или «в планах» и появятся волнами.

## Запуск для разработки

Нужен Node.js 20+.

```bash
npm install
npm run dev          # сайт: http://localhost:5173
npm run dev:server   # сервер комнат: http://localhost:8787 (нужен только для режима «через сервер»)
```

## Проверки

```bash
npm run check        # типы + тесты (обязательно перед коммитом)
npm test             # только тесты
SIM_GAMES=40 npm test  # длинный прогон: по 40 партий ботов на каждое число игроков
```

Тесты (`tests/`) без браузера гоняют каждую зарегистрированную игру: боты доигрывают партии на любом
числе игроков и во всех пресетах, каждый шаг показа правил допустим, комната переживает обрыв и возврат игрока.

## Сборка и свой сервер

```bash
npm run build        # dist/ — статический сайт, dist-server/ — сервер
npm start            # раздаёт dist/ и держит комнаты на :8787 (порт — переменная PORT)
```

Без сервера сайт из `dist/` можно выложить на любой статический хостинг: локальная игра и P2P работают и так.

## Сетевая игра

- **Напрямую (P2P)** — по умолчанию. Комнату держит браузер хозяина стола, связь — WebRTC через PeerJS. Код комнаты — 5 знаков.
- **Через сервер** — партию ведёт сервер, чужие карты и роли не видит никто. Код — 6 знаков. Включается в «Настройках».

Код комнаты по длине сам подсказывает, куда подключаться. Если кто-то отключился, за него ходит бот;
вернуться можно по тому же коду (после перезагрузки вкладки сайт сам предложит вернуться).

### Деплой сервера

- **Свой сервер (прод, https://lavochka-games.ru)** — FirstVDS, nginx + systemd; устройство и выкладка — `deploy/README.md`.
- **Render.com** (бесплатно, без карты): New → Blueprint → этот репозиторий, всё описано в `render.yaml` в корне репозитория.
  Бесплатный сервер засыпает после 15 минут простоя, первое подключение ждёт до минуты. Рекорды хранятся в файле
  и на бесплатном тарифе сбрасываются при перезапуске.
- **Любой VPS**: `npm ci && npm run build && PORT=80 npm start` (или за nginx). Рекорды — в `data/` (переменная `DATA_DIR`).

## Устройство

| Папка | Что там |
|---|---|
| `src/core/` | ядро: типы игр, комната (`room.ts`), авторитетное состояние (`authority.ts`), клиент, стол, лобби, правила с показом, настройки |
| `src/core/net/` | транспорты: PeerJS (`p2p.ts`) и WebSocket (`ws.ts`) |
| `src/cards/` | колоды: модель и отрисовка в трёх стилях; `stage.ts` — общая сцена карточных игр (полёт и переворот карт, вертикальная раскладка для телефона) |
| `src/launcher/` | двор-лаунчер |
| `src/games/catalog.ts` | каталог всех игр сборника |
| `src/games/<игра>/` | игра: `def.ts` (правила, боты, показ — без DOM), `view.ts` (отрисовка) |
| `server/` | сервер Node: комнаты, раздача сайта, рекорды |

**Как добавить игру.** Описать `GameDef` (setup / toAct / apply / view / result / bot / rules) и `GameView`
(mount / setView / play / setTurn), зарегистрировать в `catalog.ts` и `defs.ts`. Сеть, лобби, переподключение,
боты вместо отключившихся, журнал, чат и автосохранение достаются игре даром.

**Лобби комнаты** (`session.ts` → `buildLobby`, протокол 3): до старта хозяин меняет пресет, варианты и число мест
(`host/setup`), отдаёт место боту, сети или себе, меняет двух игроков местами (так выбирают пары), рассаживает случайно,
выгоняет; гость садится на свободное место (`sit`); каждый задаёт имя, аватар и персонажа (`me`). Командная игра
описывает пары в `GameDef.teams(opts, seats)` (`core/teams.ts`) — лобби подписывает команды, `tests/presets.test.ts`
проверяет, что командный пресет при каждом допустимом числе мест и правда даёт команды (если нет — нужен `countsFor`).
Игра со своими персонажами даёт `GameModule.looks`, а за столом спрашивает `ctx.look(seat)` (холдем 3D).

**Игры реального времени** (настольный хоккей): у `GameDef` есть `realtime` — `tick(state, inputs, rng)` 60 раз в секунду,
`input()` чистит ввод из сети, `bot()` даёт ввод бота каждый шаг. Ходов нет: комната (`room.ts`, на сервере, у хоста P2P
или в браузере) сама крутит шаги, клиент шлёт `input` (своё текущее управление), комната рассылает снимки `rt`
(в сеть — раз в `sendEvery` шагов, на локальный экран — каждый шаг). Вид получает их в `GameView.realtime()` и сглаживает
движение между снимками. Пока у кого-то грузится стол или людей нет — пауза.
Так сделаны настольные хоккей, баскетбол и футбол. Общее — `core/realtime.ts` (настройка «Скорость игры»: физика медленнее
жизни, часы — как обычно; смена скорости за столом — поле `sp` во вводе места) и `core/rtview.ts` (переключатели в панели под столом).

**Таблицы рекордов** (`core/records.ts` — общее без DOM, `core/records-ui.ts` — окно, `server/records.ts` — хранение и API).
Игра описывает таблицы в `GameDef.records`: `columns` (`{ key, label, sort: 'asc'|'desc', format: 'time'|'score' }`, первый — главный),
`table(opts)` — таблица для этих настроек (вариант + режим; `null` — без рекордов), `score(state, { ms, actions, opts })` — итог
законченной партии (`help: true` — была отмена/подсказка, результат идёт в таблицу `…~help`). Рекорды — только у партии одного
человека. `Authority` у таких игр пишет сид, начало часов и ходы с паузами (`log`, есть и в автосохранении); время движок берёт
из `core/clock.ts` (`gameNow()`), поэтому сервер, переигрывая запись (`verifyReplay`), получает то же время и тот же счёт — и
принимает только свой пересчёт. Аркады (`ARCADE_RECORDS`) шлют очки без записи (проверка правдоподобия). Сервер:
`GET /api/records?game=&table=&period=all|month|week|mine&device=`, `POST /api/records` (не чаще 30 раз за 10 минут с адреса);
хранение — слой `RecordStore` (сейчас `FileRecordStore`, файл `DATA_DIR/records2.json`; старый `records.json` аркад
переносится при первом запуске). В таблице — лучший результат каждого игрока (до аккаунтов — по метке устройства); «мои» —
по той же метке, поле `player` — под аккаунты этапа 3. На странице игры пререндер оставляет `<!--records:игра-->`, сервер
вписывает туда свежие таблицы при каждой выдаче, браузер заменяет их живой таблицей. Новой игре с рекордами — добавить её в
`RECORD_GAMES` (тест сверяет) и, если движку нужно время, брать его из `gameNow()`.

Превью карточки снимается со страницы `/?thumb=<id>` (позиция из `def.showcase()`) и кладётся в `public/thumbs/`.

**Адреса и SEO-страницы** (`src/site/`). Каждый экран — свой адрес: двор `/`, группа `/priklyucheniya/`, игра `/nardy/`,
вариант со своим спросом `/nardy/dlinnye/`, правила `/nardy/pravila/`, партия за этим экраном — адрес игры с `?igra`,
сетевой стол — `/stol/<код>`. Таблица адресов — `routes.ts` (у каждой карточки каталога должен быть адрес — проверяет
`tests/routes.test.ts`); роутер — в `main.ts`: обновление страницы открывает то же самое (посреди партии — продолжает её,
за сетевым столом — переподключает), «назад»/«вперёд» браузера ходят по экранам.
`npm run build` после `vite build` запускает `tools/prerender.ts`: готовый HTML на каждую игру, вариант и правила
(заголовки, текст, варианты, правила целиком, FAQ, schema.org), `sitemap.xml`, `robots.txt`; чистая оболочка — `dist/_spa.html`
(её сервер отдаёт столам и неизвестным адресам с `noindex`). Тексты — `src/games/<игра>/seo.ts` (`GameSeo`); где их нет,
пререндер собирает текст из каталога и правил, у страниц вариантов текст обязателен (тест). В браузере текст страницы
встаёт под экраном игры (`site/page.ts`). Тексты любой страницы (заголовок вкладки, описание, H1, вводный текст, FAQ,
у статей и документов — сам текст, у разделов — абзац на главной) Мастер правит в админке («Тексты» → «Страницы сайта»,
`site/admin-pages.ts`): пререндер пишет исходные в `dist/texts.json`, правки (только отличия) сервер выгружает
в `DATA_DIR/pages.json`, и пререндер кладёт их поверх (`editable()` в `tools/prerender.ts`). Адрес сайта для canonical и sitemap — `SITE_URL` (по умолчанию `lavochka-games.ru`).
Разделы двора — свои страницы (`SECTION_SLUGS`: `/kartochnye-igry/`, `/golovolomki/`…) со связным текстом из `site/sections.ts`
(там же тексты главной и карточек-групп); кнопки разделов во дворе — ссылки на них. Карточки игр — одна разметка `site/card.ts`
и во дворе, и в готовом HTML: страницы двора несут карточки для поисковика (на экране их прячет `page.ts`, их показывает двор),
у страницы игры — «Похожие игры» карточками, снимок игры и «Как ещё называют» (`site/names.ts`: русские и английские названия,
они же — `alternateName` в разметке и синонимы поиска). Шапка страниц игр — `site/bar.ts`. Поиск `/poisk/?q=` — `site/search.ts`
(названия, подписи, варианты, другие названия; транслит, чужая раскладка, опечатки), показывает найденное во дворе, `noindex`.
Переехавшие адреса — `MOVED` в `routes.ts` (сервер отвечает 301).
Статьи при игре — `ARTICLES` в `routes.ts` (`/poker/kombinacii/`): экран игры, а под ним текст статьи из `seo.ts`
(`articles[slug]`), и страница сама прокручивается к нему. Игры серии у аркад — `MODE_PAGES` (`/elektronika/nu-pogodi/`,
`/avtomaty/tetris/`): адрес открывает прибор сразу на этой игре, а выбор другой игры меняет адрес; текст страниц пререндер
собирает из `games.ts` аркады. Снимки вариантов — `public/thumbs/v/<адрес через дефис>.webp` (og:image и снимок на странице
варианта; нет снимка — берётся снимок игры): `/?thumb=<игра>&preset=<вариант>&steps=N` — позиция после N ходов ботов,
снимает `python tools/thumbs/variant.py <адрес> <игра> <вариант> [--steps --top]` (нужен `npm run dev`).
IndexNow и даты в sitemap — `tools/indexnow.mjs`, его запускает выкладка (`deploy/README.md`).
**Шапка сайта** — `site/bar.ts`, одна на двор (поверх двора, без своей строки поиска), экран игры и страницы новостей/блога;
за столом с партией шапки нет. Баннер: название, счётчик «во дворе», поиск, вход по коду, настройки, место под вход/профиль;
под ним вкладки `TABS` (у неоткрытых разделов нет адреса — табличка «скоро»). На телефоне — название, профиль значком и «меню».
**Новости и блог** — Markdown в `content/news/*.md` и `content/blog/*.md` (адрес — имя файла, шапка записи и разметка — в
`tools/posts.ts`). Пререндер пишет списки `/novosti/`, `/blog/` (по 10, дальше `/novosti/stranica-2/`), страницы записей
(`NewsArticle`/`BlogPosting`), свежие записи на главной и «Статьи об игре» на страницах игр из поля `games` записи.
В браузере это экран `page` в `main.ts`: шапка + готовый текст адреса. Тест `tests/posts.test.ts` проверяет шапку записи и что
ссылки в тексте ведут на настоящие страницы.
**Счётчики двора** — `site/stats.ts` и `/api/stats` на сервере: онлайн (вкладки, отметившиеся за 3 минуты) и начатые партии
по играм (`/api/played` при «Начать»/«Сыграть ещё», у аркад — при запуске игры; лимит с одного адреса, `data/played.json`),
ответ кэшируется на минуту. Порядок карточек во дворе: как обычно / сначала новые (поле `added` в каталоге) / популярные.

## Аккаунты (этап 3а)

- Сервер: `server/accounts/` — `accounts.ts` (регистрация, вход, сессии, письма, права; без HTTP), `http.ts` (`/api/auth/me|register|login|logout|confirm|resend|forgot|reset|profile`), `store.ts` (интерфейс и хранилище в памяти), `pg.ts` (PostgreSQL и миграции), `crypto.ts` (scrypt, токены, TOTP), `mail.ts` (Unisender Go). Хранилище — PostgreSQL, если задан `PGDATABASE`, иначе в памяти (разработка, тесты).
- Сессия — httpOnly-cookie `lv_sid` на 90 дней; в базе — только хеши сессий и ссылок из писем. POST только с JSON и со своего Origin.
- Почта: `UNISENDER_API_KEY` + `UNISENDER_HOST`; без ключа писем нет, регистрация и вход работают. Свой предел — 90 писем в сутки (тариф 100), частота писем на игрока и на адрес ограничена.
- Права — `src/core/rights.ts` (`video`, `early_access`, `ai`, `cosmetics`, `lobby_host`, `moderator`, `master`) с датой окончания; голос — бесплатный всем. Мастер (`master`) заводится командой на сервере и входит только с кодом из приложения (TOTP).
- Сайт: `src/site/account.ts` — кто вошёл, окно входа/регистрации, профиль; кнопка в шапке. Ссылки из писем — `/vhod/?podtverdit=…`, `/vhod/?sbros=…`.
- Политика конфиденциальности и условия — `content/pages/politika.md`, `usloviya.md` → `/politika/`, `/usloviya/` (пререндер).
- Команды на сервере — `server/admin.ts` (собирается в `dist-server/admin.js`), обёртка `deploy/lavochka-admin.sh`.

## Аккаунты, этап 3б: вход через сервисы, лайки, история

- **Яндекс ID и VK ID** — `server/accounts/oauth.ts`: `/api/auth/<yandex|vk>/start?back=…` → сервис (код + PKCE S256, state в памяти + cookie `lv_oa`) → `/api/auth/<…>/callback` → обмен кода и данные игрока на сервере → сессия и назад с `?voshel=…`. Ошибки — `/vhod/?oshibka=<код>`. Ключи: `YANDEX_CLIENT_ID/SECRET`, `VK_APP_ID` (+ `VK_CLIENT_SECRET`); без ключей кнопок нет (`/api/auth/me` → `loginWith`).
- Аккаунт для входа через сервис (`Accounts.externalLogin`): по привязке → по почте (неподтверждённый аккаунт с той же почтой забирается: чужой пароль и сессии сбрасываются) → новый. Мастеру вход через сервис закрыт. Вошедший привязывает вход из профиля, отвязать (`/api/auth/unlink`) можно не последний способ входа.
- Имя за столом у вошедшего — имя аккаунта (`site/account.ts` синхронизирует с настройками в обе стороны). Рекорды вошедшего пишутся на него (`player`), «мои» — с любого устройства.
- **Лайки и история** — `server/player.ts`: `/api/likes` (свои; счётчики всех игр — в `/api/stats` → `likes`), `/api/history`. Клиент: `site/likes.ts` (кнопка ♥ на экране игры через `HomeOpts.topExtra`, счётчик на карточке, порядок «любимые»), `site/history.ts` («Мои партии» в профиле; конец партии ловит `tableHooks.finished` в `core/table.ts`, что записать — `core/history.ts`). Миграция 3: `game_likes`, `game_history`.
- Проверять POST-запросы надо на собранном сайте на :8787: через dev-прокси на :5174 сервер отклоняет их по Origin.

## Поддержка проекта (донат)

- Кнопка в шапке левее кода стола (на телефоне — в меню), окно с суммами 100/300/500/1000 ₽ и своей (10–50 000 ₽) — `src/site/donate.ts`, общее — `src/core/donate.ts`.
- Сервер — `server/donate.ts` (`/api/donate`, уведомления `/api/pay/robokassa/result`, возврат `…/success|fail` → `/?donate=spasibo|otmena`), Robokassa — `server/pay/robokassa.ts` (POST-форма, подпись, номенклатура чека для самозанятого). Донаты и настройки — таблицы `donations`, `site_settings` (миграция 2).
- Ключи: `ROBOKASSA_LOGIN`, `ROBOKASSA_PASS1`, `ROBOKASSA_PASS2`, `ROBOKASSA_TEST=1` (тестовые пароли магазина), `ROBOKASSA_HASH` (алгоритм из настроек магазина, по умолчанию md5), `ROBOKASSA_RECEIPT=0` — не передавать чек. Без ключей кнопка есть, а окно пишет «приём платежей скоро откроется».
- Надпись кнопки и цель сбора (название, описание, сколько собрать, начать счёт заново) — Мастер: профиль → «Поддержка проекта». Там же — всего получено и последние поступления.

## Подписка «Лавочка+»

- 299 ₽ за 30 дней (`src/core/plus.ts`): права `video` и `early_access` до конца срока; повторная оплата прибавляет 30 дней к концу срока (истёк — к дню оплаты). Голос бесплатный, косметика и ИИ войдут в `PLUS_RIGHTS`, когда появятся. Бессрочные или более долгие права от Мастера подписка не урезает.
- Сервер — `server/plus.ts` (`/api/plus` статус и заказ, `/api/plus/autorenew`, `/api/admin/plus`). Уведомления — тот же Result URL, что у доната: номера заказов подписки — с 1 000 001 (`PLUS_INV_FROM`), `server/donate.ts` отдаёт их в `Plus.result`; возврат — `/?plus=spasibo|otmena`. Таблицы `plus_orders`, `subscriptions` (миграция 9); заказ засчитывается один раз — `payPlusOrder` в одной транзакции отмечает оплату и продлевает срок.
- Клиент — `src/site/plus.ts`: окно «Лавочка+» (профиль → «⭐ Лавочка+», ссылки `#plus` и `[data-plus]` на любой странице, в том числе в тексте `/podpiska/`), записки «это в подписке» у камеры и у игр раннего доступа, админка → «⭐ Подписки».
- **Камера** — только с правом `video`: сервер пишет право в канал комнаты (`Link.video`), комната ставит участнику `video: false` и в его SDP переводит видео на «только приём» (`noVideoSend` в `core/room.ts`) — чужие камеры он видит, свою не шлёт. В P2P-комнатах проверяет только браузер.
- **Автопродление** — `ROBOKASSA_RECURRING=1`, включать только когда Robokassa подключит повторные платежи магазину (тестового режима у них нет). Тогда в окне — флажок согласия (не отмечен), первая оплата идёт с `Recurring=true`, раз в час `Plus.tick` за 2 дня до конца шлёт напоминание, в последние сутки — запрос на `Merchant/Recurring` (не вышло — снова через сутки, 3 дня после конца срока). Без флага — только напоминание на почту «заканчивается, продлите».

## Обращения: поддержка, ошибки, почта домена

- Личная почта на сайте не светится: контакт — `support@lavochka-games.ru` (`SUPPORT_EMAIL` в `src/core/support.ts`), об ошибках — ещё и `bugs@`.
- **С сайта** — окно «Написать нам» (`src/site/support.ts`): любая ссылка `…#napisat` (подвал, «Контакты») и меню стола ☰ → «Ошибка?» (приложит игру, режим и настройки партии); само прикладывает страницу, браузер, экран. Гостю почта необязательна, вошедшему ответ приходит и в профиль («✉ Мои обращения»).
- **Письмом** — Postfix на сервере (`deploy/mail/`, см. `deploy/README.md`) отдаёт письмо в `/api/mail/in` → обращение; «[№N]» в теме от того же адреса дописывает в обращение N, цитата старого письма отрезается, автоответы отбрасываются.
- **Мастер** — профиль → «📮 Обращения»: ждущие ответа и все, переписка, ответ (уходит письмом от `support@` через Unisender, с `[№N]` в теме) и состояние новое/отвечено/закрыто. О новом обращении Мастерам приходит короткое письмо со ссылкой `/?obrashenie=N`.
- Сервер — `server/support.ts` (`/api/support`, `/api/support/reply`, `/api/admin/support`), таблицы `tickets`, `ticket_messages` (миграция 5), тесты — `tests/support.test.ts`. Пределы: обращений с адреса 6/час, писем с одного отправителя 10/час, уведомлений Мастеру 25 и ответов 40 в сутки (Unisender даёт 100 писем в сутки на всё).
