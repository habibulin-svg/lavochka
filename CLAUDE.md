# CLAUDE.md — «Вечером на лавочке»

Сборник браузерных дворовых игр (~40 игр) в стиле российского двора 90-х. Общение с пользователем — по-русски.

- `lavochka/` — сборник (Vite + TypeScript + сервер Node). **Вся работа идёт здесь.**
- корень (`index.html`, `js/`, `css/`) — старая версия Шиш-беша. **Не трогать**, это резерв.
- `materials/` — сканы полей ходилок/экономических игр, **только для личного использования**: в git только `README.md` со ссылками.
- `docs/STATE.md` — состояние проекта и план. Читать в начале работы (хук подкладывает сам), обновлять в конце каждой крупной задачи.

## Команды (из `lavochka/`)

Node установлен в `C:\Program Files\nodejs`; в Bash сначала `export PATH="/c/Program Files/nodejs:$PATH"`.

| Команда | Что делает |
|---|---|
| `npm run dev` | сайт на :5173 (в превью — конфигурация `lavochka` из `.claude/launch.json`) |
| `npm run dev:server` | сервер комнат на :8787 (конфигурация `lavochka-server`); Vite проксирует к нему `/ws` и `/api` |
| `npm run check` | `tsc --noEmit` + все тесты — **обязательно перед коммитом** |
| `npm test` | только тесты; `SIM_GAMES=40 npm test` — длинный прогон ботов |
| `npm run build` | `dist/` (сайт) + `dist-server/` (сервер) |

## Устройство

Подробно — `lavochka/README.md`. Коротко:
- `src/core/room.ts` — комната, один код для браузера хоста (P2P/локально) и сервера. `authority.ts` — состояние и rng. Клиент — `client.ts`, стол — `table.ts`, лобби/сессии — `session.ts`, экран настройки — `home.ts`, правила с показом — `rules.ts`.
- Игра = `src/games/<id>/def.ts` (`GameDef`: правила, боты, показ правил, `showcase` — **без DOM**, его гоняет сервер и тесты) + `view.ts` (`GameView`: отрисовка) + `index.ts`. Регистрация: `src/games/catalog.ts` (карточка) и `src/games/defs.ts` (сервер). Тест сверяет, что списки совпадают.
- Скрытая информация (карты, роли): только через `def.view(state, seats)` и `def.redact(event, seats)`. Клиент никогда не получает чужое.

## Требования к каждой игре

- Боты: минимум 3 уровня (`Лёгкий/Средний/Сложный`), бот видит только свой `view`.
- Варианты правил — через `options` + `presets`; в лаунчере **одна карточка на игру**, варианты строкой внизу карточки, выбор — на экране игры.
- Правила: цель + разделы; у каждого ключевого правила — `demo` (пошаговый показ на настоящем поле, кубики/раздачи подкручиваются `rig`).
- Превью карточки: `def.showcase()` → открыть `/?thumb=<id>` в превью, снять скриншот, обрезать в `public/thumbs/<id>.webp` (480×300), прописать `thumb` в каталоге.
- Стилизация под тему — где уместно (двор, 90-е, советские коробки), но не в ущерб читаемости.
- «Электроника ИМ» и кинь-двинь делаются максимально как оригинал (решение пользователя) — значит, **такие игры не публиковать как Artifact** и не выкладывать отдельно; репозиторий приватный.

## Проверка

- Логика — харнесс `lavochka/tests/` (партии ботов против ботов для всех игр из `DEFS`, показ правил, комната с обрывом/возвратом). Новая игра покрывается автоматически, если зарегистрирована в `defs.ts`.
- Интерфейс — проверять в превью браузера (`preview_start lavochka`), скриншот как доказательство. Сеть — две вкладки (clientId свой у каждой вкладки).
- Хук Stop сам запускает `tsc` + тесты, если код сборника менялся. Если он вернул ошибки — чинить, а не обходить.

## Правила работы (от пользователя)

1. **После каждой крупной задачи и тестов:** коммит → пуш → обновить `docs/STATE.md` (что сделано, что дальше, известные проблемы) → предложить пользователю `/clear` для сброса контекста. Крупная задача — это игра, волна, заметная подсистема или серия правок по просьбе пользователя.
2. Коммиты — на русском, по делу, с трейлером `Co-Authored-By` из системной подсказки. Пуш — `git push` в `origin main` (адрес с `habibulin-svg@`). Force-push запрещён (хук не даст).
3. Пуш в `main` автоматически деплоит Render — пушить только то, что прошло `npm run check`.
4. **Автономный режим.** Если пользователь говорит работать автономно — делать задачи из `docs/STATE.md` по порядку без вопросов, сомнительные решения принимать самому и записывать в раздел «Решения, принятые без пользователя». На случай лимитов:
   - в настройках проекта включено `autoContinueAtUsageLimit` — после сброса лимита работа продолжится сама;
   - дополнительно в начале автономной работы поставить страховочный таймер: `CronCreate` (recurring, раз в ~2 часа, минута не :00/:30) с промптом «Продолжи автономную работу по docs/STATE.md с места остановки»; когда автономная работа закончена — `CronDelete`. Таймеры живут только в этой сессии и истекают через 7 дней.
   - Каждую законченную игру — сразу коммит + пуш + STATE.md, чтобы прерывание ничего не теряло.
5. Не начинать игры волны 7 без материалов из `materials/README.md`. «Подарок менеджера» не делаем.
