# CLAUDE.md — «Вечером на лавочке»

Сборник браузерных дворовых игр (~40 игр) в стиле российского двора 90-х. Общение с пользователем — по-русски.

- `lavochka/` — сборник (Vite + TypeScript + сервер Node). **Вся работа идёт здесь.**
- корень (`index.html`, `js/`, `css/`) — старая версия Шиш-беша. **Не трогать**, это резерв.
- `materials/` — сканы полей ходилок/экономических игр, **только для личного использования**: в git только `README.md` со ссылками.
- `docs/STATE.md` — состояние проекта и план: **только открытое и последние волны** (держим коротким). Читать в начале работы (хук подкладывает сам), обновлять в конце каждой крупной задачи.
- `docs/JOURNAL.md` — журнал: подробные записи по закрытым волнам и полные версии недавних разделов. Целиком не читать — искать по разделу; закрывая задачу, её запись из STATE.md переносим сюда.

## Команды (из `lavochka/`)

Node установлен в `C:\Program Files\nodejs`; в Bash сначала `export PATH="/c/Program Files/nodejs:$PATH"`.

| Команда | Что делает |
|---|---|
| `npm run dev` | сайт на :5173 (в превью — конфигурация `lavochka` из `.claude/launch.json`) |
| `npm run dev:server` | сервер комнат на :8787 (конфигурация `lavochka-server`); Vite проксирует к нему `/ws` и `/api` |
| `npm run check:quick` | `tsc` + общие тесты; партии ботов и собственные тесты игр — только тех игр, чьи папки менялись (~1 мин; задеты `core`/`cards`/харнесс — всё); по ходу работы и в Stop-хуке |
| `npm run check` | `tsc` + все тесты полностью (~6 мин) — **перед пушем** |
| `npm test` | только тесты; `SIM_GAMES=40 npx vitest run tests/games-` — длинный прогон ботов |
| `npm run build` | `dist/` (сайт) + `dist-server/` (сервер) |

## Устройство

Подробно — `lavochka/README.md`. Коротко:
- `src/core/room.ts` — комната, один код для браузера хоста (P2P/локально) и сервера. `authority.ts` — состояние и rng. Клиент — `client.ts`, стол — `table.ts`, лобби/сессии — `session.ts`, экран настройки — `home.ts`, правила с показом — `rules.ts`.
- Игра = `src/games/<id>/def.ts` (`GameDef`: правила, боты, показ правил, `showcase` — **без DOM**, его гоняет сервер и тесты) + `view.ts` (`GameView`: отрисовка) + `index.ts`. Регистрация: `src/games/catalog.ts` (карточка) и `src/games/defs.ts` (сервер). Тест сверяет, что списки совпадают.
- Скрытая информация (карты, роли): только через `def.view(state, seats)` и `def.redact(event, seats)`. Клиент никогда не получает чужое.

## Требования к каждой игре

- Боты: минимум 3 уровня (`Лёгкий/Средний/Сложный`), бот видит только свой `view`.
- Варианты правил — через `options` + `presets`; в лаунчере **одна карточка на игру**, варианты строкой внизу карточки, выбор — на экране игры.
- Правила: цель + разделы; у каждого ключевого правила — `demo` (пошаговый показ на настоящем поле, кубики/раздачи подкручиваются `rig`).
- Превью карточки: `def.showcase()` → открыть `/?thumb=<id>` в превью, снять скриншот, обрезать в `public/thumbs/<id>.webp` (480×300), прописать `thumb` в каталоге.
- **Сетевой стол (решение пользователя):** в каждой сетевой игре — вкладка «Чат» рядом с «Журналом» и голос/камера (`core/voice.ts`, WebRTC каждый с каждым). Это общее в `core/table.ts` — игра не прячет и не подменяет панель стола (`.voice`, `.tabs`), а если у неё своя раскладка, оставляет их видимыми и на телефоне. Тишину (ночь в мафии) просит через `GameView.quiet`. Голос без TURN за строгим NAT не соединяется — TURN выдаёт сервер (`/api/ice`, переменные `TURN_URLS`/`TURN_USERNAME`/`TURN_CREDENTIAL` на Render; Cloudflare из РФ не подходит). Бросок кубиков и подобная главная кнопка хода — с атрибутом `data-tap`: стол нажимает её тапом по свободному месту доски.
- **ИГРЫ НЕ ИГРАЮТ САМИ В СЕБЯ (решение пользователя).** Ход человека делает сам человек: в бродилках/ходилках после броска кубика (компаса, вертушки) фишка не едет сама — игрок сам переставляет её на подсвеченную клетку (образец — кинь-двинь: фаза `move`, «взял пуговицу — поставил»). Ход бота — тоже отдельным действием. Но без лишней возни: по однозначной дороге путь прокладывается целиком, игрок выбирает только на развилках (образец — «Джио-Джанги»), а не тащит фишку по одной клетке.
- **Страница игры на сайте** (подробно — `lavochka/README.md`, «Адреса и SEO-страницы»):
  - адрес — `SLUGS` в `src/site/routes.ts`, транслитом (`/nardy/`); без него тест не пройдёт;
  - тексты — `src/games/<id>/seo.ts`: `title`, `h1`, `description`, `intro`, `faq` (4–5 вопросов), при желании `rules`. Ключевые фразы — `docs/seo/games.json`, Wordstat — `tools/seo/wordstat.mjs`. Факты — только из `def.ts`; массовые тексты пишут агенты на Sonnet, я проверяю;
  - другие названия, русские и английские, — `src/site/names.ts` (по ним работают поиск и `alternateName`);
  - вариант с собственным спросом — `VARIANTS` в `routes.ts` плюс текст `seo.ts` → `variants[preset]` (тест требует) и снимок `python tools/thumbs/variant.py <адрес> <игра> <пресет>` → `public/thumbs/v/`;
  - аркада с серией игр — `MODE_PAGES`; справочная статья с большим спросом («комбинации покера») — `ARTICLES` + `seo.ts` → `articles`;
  - новый раздел двора — `SECTION_SLUGS` + текст в `src/site/sections.ts`;
  - карточка в каталоге — с датой появления `added: 'ГГГГ-ММ-ДД'` (сортировка «сначала новые»);
  - новость о новой игре и статьи блога — Markdown в `lavochka/content/news/`, `lavochka/content/blog/` (формат — `tools/posts.ts`; `games:` в шапке записи ставит её в «Статьи об игре»);
  - проверка — `npm run build`, затем адрес на `:8787` (`lavochka-server`): текст под игрой, заголовок вкладки. В `npm run dev` текста страниц нет. Sitemap и IndexNow обновляются сами при выкладке;
  - временное (безголовый Chrome, логи) — на G: `TEMP=G:/temp TMP=G:/temp` (диска D после переезда нет).
- Стилизация под тему — где уместно (двор, 90-е, советские коробки), но не в ущерб читаемости.
- «Электроника ИМ» и кинь-двинь делаются максимально как оригинал (решение пользователя). Поля кинь-двинь — советское наследие, **публичные** (картинки в `public/hodilki/`); все кинь-двинь — одна карточка с выбором поля.

## Проверка

- Логика — харнесс `lavochka/tests/` (партии ботов против ботов для всех игр из `DEFS`, показ правил, комната с обрывом/возвратом). Новая игра покрывается автоматически, если зарегистрирована в `defs.ts`.
- Интерфейс — проверять в превью браузера (`preview_start lavochka`), скриншот как доказательство. Сеть — две вкладки (clientId свой у каждой вкладки).
- Хук Stop сам запускает `tsc` + тесты, если код сборника менялся. Если он вернул ошибки — чинить, а не обходить.

## Правила работы (от пользователя)

1. **После каждой крупной задачи и тестов:** коммит → пуш → обновить `docs/STATE.md` (что сделано, что дальше, известные проблемы) → предложить пользователю `/clear` для сброса контекста. Крупная задача — это игра, волна, заметная подсистема или серия правок по просьбе пользователя.
2. Коммиты — на русском, по делу, с трейлером `Co-Authored-By` из системной подсказки. Пуш — `git push` в `origin main` (адрес с `habibulin-svg@`). Force-push запрещён (хук не даст).
3. Пуш в `main` автоматически выкладывается на сайт (свой сервер подтягивает `main` за 2–5 минут) — пушить только то, что прошло `npm run check`.
   - **Срочный фикс (решение пользователя 2026-10-20):** правку в пару строк, которая чинит сломанное на проде и которую ждёт пользователь, пушить сразу после `tsc --noEmit`, сборки и проверки в браузере — без полного `npm run check`.
   - **Проверки (решение пользователя 2026-10-23):** по ходу этапа — `npm run check:quick` и тесты своей игры; полный `npm run check` — один раз перед пушем в конце большого этапа. Если полный прогон упал и правка точечная — чинить и гонять упавший файл + `check:quick`, а не весь check заново.
   - **Пушить пореже (решение пользователя):** `npm run check` идёт ~6 минут, поэтому мелкие правки не пушим по одной — копим и выкладываем крупными кусками, одним прогоном проверки на всё. Коммитить можно чаще, пушить — когда кусок работы закончен. Правки только в `docs/` проверки не требуют, но и их лучше присоединять к ближайшему пушу кода.
4. **Автономный режим.** Если пользователь говорит работать автономно — делать задачи из `docs/STATE.md` по порядку без вопросов, сомнительные решения принимать самому и записывать в раздел «Решения, принятые без пользователя». На случай лимитов:
   - в настройках проекта включено `autoContinueAtUsageLimit` — после сброса лимита работа продолжится сама;
   - дополнительно в начале автономной работы поставить страховочный таймер: `CronCreate` (recurring, раз в ~2 часа, минута не :00/:30) с промптом «Продолжи автономную работу по docs/STATE.md с места остановки»; когда автономная работа закончена — `CronDelete`. Таймеры живут только в этой сессии и истекают через 7 дней.
   - Каждую законченную игру — сразу коммит + пуш + STATE.md, чтобы прерывание ничего не теряло.
   - **Сессия на игру (решение пользователя 2026-10-15):** в автономном режиме каждую следующую игру основная сессия отдаёт в **новую сессию** (`start_session`, `context: "fresh"`, свой worktree не нужен — одна игра за раз, в той же папке) с коротким заданием «сделай X по docs/STATE.md и CLAUDE.md: игра, пресеты, боты, правила с показом, превью, проверка в браузере, коммит + пуш + STATE.md». Сессия стартует с чистым контекстом; когда она отчитается, основная сессия **проверяет результат по коду и коммиту** (git log/diff, тесты), а не верит отчёту на слово, и запускает следующую. Плата — каждая сессия заново читает проект (дороже по лимиту), зато контекст не разрастается.
5. Не начинать игры волны 7 без материалов из `materials/README.md`. «Подарок менеджера» не делаем.
6. **Агенты на Haiku (решение пользователя).** Поиски и тесты не делать самому, а отдавать агентам из `.claude/agents/` (модель haiku):
   - `searcher` — поиск по коду и в интернете (правила игр, варианты, справки); только читает;
   - `tester` — `npm run check`, отдельные тесты, длинные прогоны ботов, сборка; докладывает падения с `файл:строка`, код не правит.
   Короткие точечные действия (прочитать известный файл, один grep по известному месту) можно делать самому. Перед коммитом `npm run check` всё равно должен пройти — через `tester` или Stop-хук.
7. **Не оставлять за собой работающие прогоны.** Проверил в превью — сразу закрыть вкладку с партией (`tabs_close`) или уйти со стола: партия ботов в фоне играет звуки у пользователя. То же для фоновых команд и агентов, которые больше не нужны (`TaskStop`). Dev-серверы `lavochka` / `lavochka-server` можно не останавливать — они беззвучные.
